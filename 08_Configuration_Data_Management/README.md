# 08 Configuration and Data Management (PDR deliverable 8)

**Deliverable:** Configuration management and data management baseline plan. **Owner:** Jash Joshi.
# Configuration Management Baseline Plan

## 4. Controlled Configuration Items

The following project artifacts are controlled:

- System and technical requirements
- ConOps and stakeholder documents
- Capella models
- IDEF0 diagrams
- Logical architecture
- Interface documents and ICDs
- Risk and FMEA documents
- Analysis and simulation results
- Verification and validation documents
- Project-management files
- PDR report and presentation

---

## 5. Version Control

Working versions use the following format:

`v0.x`

Example:

`v0.1 → v0.2 → v0.3`

The configuration approved during PDR becomes:

`v1.0`

This version represents the **PDR baseline**.

---

## 6. Change Management

Changes to an approved baseline follow the process:

`Change Request → Impact Assessment → Review / Approval → Update → New Version`

For each important change, the team records:

- What was changed
- Why it was changed
- Who made the change
- Which requirements or interfaces are affected
- Which files or models must be updated

---

# Data Management Baseline Plan

## 7. Data Management

Project data is organized by workstream and maintained in the common project repository.

Main data categories include:

- Requirements
- Models
- Diagrams
- Architecture files
- Interface definitions
- Analysis and simulation results
- Risk and safety files
- Verification results
- Project-management files
- PDR documentation

Each controlled artifact should have:

- Clear ownership
- Version identification
- Change history
- Defined storage location
- Traceability to related project information

---

## 8. Traceability

The project maintains traceability between:

`Stakeholder Need → Requirement → System Function / Architecture → Verification Method → Verification Result`

This ensures that every important requirement can be linked to:

- Why it exists
- Where it is implemented
- How it will be verified

---

## 9. PDR Baseline

The purpose of the PDR baseline is to establish one consistent system definition for further development.

The PDR baseline should include:

- Approved system and technical requirements
- Stakeholder analysis and ConOps
- Functional and logical architecture
- Capella models
- IDEF0 models
- Interface definitions
- Risk and FMEA results
- Analysis and simulation results
- Verification and validation plan
- Project-management documentation

After PDR approval, major changes should follow the defined change-management process.

---

## 10. Main PDR Management Objective

The main objective is to ensure that:

> **All requirements, models, interfaces, analyses, risks and verification activities are consistent, traceable and controlled under one agreed PDR baseline.**
